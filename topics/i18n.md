# Typography Details and i18n / RTL

> The main file covers hierarchy; this one covers "how type is set, and how it survives a language switch." Web by default; §8 covers iOS/Android.
> Principle: **Copy is a variable. Layout must not assume its length, direction, or character set.**

## 1. Mixed Chinese and Latin

- Leave a visual gap of about 1/4 em between Chinese and Latin letters/digits:
  - Progressive enhancement: `text-autospace: normal;` (added automatically by supporting browsers).
  - Fallback: insert a manual space (`Figma 文件`, `12 GB`), but don't pile up `&nbsp;`.
- Use full-width Chinese punctuation: `，。；：？！“”‘’（）【】`; ellipsis `……`; em dash `——`.
- No space between Chinese and full-width punctuation; spacing between Chinese and half-width parentheses/slashes follows the brand spec consistently.
- Don't apply negative letter-spacing to Chinese in mixed setting; Latin display headings may use `letter-spacing: -0.01em`.
- Don't use italics to emphasize Chinese; use weight or color.
- Preserve the original casing of English proper nouns: `iOS`, `GitHub`, `JavaScript` — never `Ios`.

## 2. Punctuation Spacing and Line Breaking

```css
:lang(zh) {
  line-break: strict;          /* avoid 。，） at line start */
  overflow-wrap: anywhere;     /* keep long URLs/English words from breaking the container */
  word-break: normal;
  text-spacing-trim: trim-start; /* progressive enhancement: trim punctuation at line start */
  hanging-punctuation: first last; /* limited support; treat as enhancement */
}
h1, h2, h3 { text-wrap: balance; }   /* more balanced two-line headings */
p { text-wrap: pretty; }             /* avoid orphan words at paragraph end */
```

- Line-start prohibition: `。，、；：？！）】》」』` must not start a line; line-end prohibition: `（【《「『` must not end a line.
- Long English words/URLs: `overflow-wrap: anywhere`; code blocks: `overflow-x: auto`.
- Korean: `word-break: keep-all`; Japanese: `line-break: strict` + `word-break: normal`.
- Don't fit two-line headings into a fixed height; use `min-height` + `text-wrap: balance`.

## 3. Numbers, Dates, Units

- Tables/amounts/counts/countdowns: `font-variant-numeric: tabular-nums`.
- Amounts carry currency and thousands separators: `¥12,800`, `$1,280.00`; decimal places stay consistent.
- Don't mix `2026/11/6` with `11-06`; use `Intl.DateTimeFormat` per locale.
- Put a space between number and unit: `12 GB`, `30 ms` — except `45°`.
- Percentages, multipliers, and signs use the same size as the number; up/down uses arrow + sign + color as triple encoding.

```js
new Intl.NumberFormat('zh-CN', { style: 'currency', currency: 'CNY' }).format(12800);
new Intl.DateTimeFormat('zh-CN', { dateStyle: 'medium' }).format(new Date());
```

## 4. RTL (Arabic / Hebrew)

**Layout**

- Root element: `<html lang="ar" dir="rtl">`; use `dir="rtl"` for local scopes.
- Use logical properties only: `margin-inline-start`, `padding-inline`, `inset-inline`, `border-inline-start`, `text-align: start`. Never `left/right`.
- Flex/Grid row direction follows `dir`; don't hard-code left/right with `order`.
- Sidebars, back arrows, progress bars, and carousel direction all mirror; decide per language whether chart axes flip.
- Scrollbar position in RTL is handled by the browser; don't hijack it with custom code.

**Icons and Media**

- Mirror directional icons: back/forward, arrows, chevron, undo/redo, list indentation.
- Don't mirror: brand logos, clocks, play/pause, media controls, people, product images, images containing text.
- Don't bake text into images; overlay real text instead.

**Text**

- Usernames/URLs/emails inside RTL paragraphs: use `<bdi>` or `unicode-bidi: isolate` to prevent ordering glitches.
- Phone/email/code inputs: `dir="ltr"`, but labels follow page direction.
- Arabic needs larger line-height (1.8–2.0); no faux bold; use Noto Sans Arabic / Noto Naskh Arabic.
- Numbers in RTL usually stay Western digits; output them via `Intl`, never assemble by hand.

```html
<p>تم حفظ الملف <bdi>report-2026.pdf</bdi> بنجاح.</p>
<input type="email" dir="ltr" inputmode="email">
```

## 5. Text Expansion and Truncation

- German/Finnish can run 30–40% longer than English; buttons, labels, and tabs must not have fixed widths.
- Where two lines are allowed, set `min-height`, not `height`; never shrink the font size to force a fit.
- Truncate only secondary information: `text-overflow: ellipsis` + `title`/tooltip; never truncate critical information.
- Reserve space for the longest language in empty states, errors, and button copy.
- Don't use `text-transform: uppercase` for Turkish (the i/İ problem) or German ß.

## 6. Fonts and Language Stacks

```css
:lang(zh) { font-family: "PingFang SC", "Noto Sans SC", "Microsoft YaHei", sans-serif; }
:lang(ja) { font-family: "Hiragino Sans", "Noto Sans JP", "Yu Gothic", sans-serif; }
:lang(ko) { font-family: "Apple SD Gothic Neo", "Noto Sans KR", "Malgun Gothic", sans-serif; }
:lang(ar) { font-family: "Noto Sans Arabic", "Geeza Pro", "Segoe UI", sans-serif; }
:lang(he) { font-family: "Noto Sans Hebrew", "Arial Hebrew", sans-serif; }
```

- At most two type families per product; for multilingual use system fonts first, to avoid loading a Web Font per language.
- `font-display: swap`; subset Chinese; don't use Latin-only fonts for Arabic/Hebrew.
- Don't set small Arabic/Chinese text at `font-weight: 300`; the strokes will smear.

## 8. Platform Implementation

**Web**: `<html lang>`, `dir`, `hreflang`; CSS logical properties; `Intl`; pseudo-localization testing.

**iOS**: String Catalog (`.xcstrings`) or `Localizable.strings`; `NSLocalizedString`; `Bundle.main.preferredLocalizations`; RTL with leading/trailing constraints; `semanticContentAttribute`; dates with `DateFormatter` + locale.

**Android**: `res/values-<locale>/strings.xml`; `values-ar` layouts mirror automatically (`android:supportsRtl="true"`); use `start/end` instead of `left/right`; `plurals` for plurals; `LocaleList`/`Intl`.

**Desktop (exe)**: localize window titles/menus/installers; in RTL, window controls follow the system; don't bind shortcuts to character keys.
